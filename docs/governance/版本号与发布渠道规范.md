## 一、3-tier 体系总览

| Tier | 对外名 | 内部代号 | 做什么的 | 谁用 |
|---|---|---|---|---|
| **1** | **稳定版**(Stable)| `prod` | 主推的发布物,所有功能测过 | 99% 普通用户 |
| **2** | **预览版**(Preview)| `dev` | 公开发布的"预览版"(显示名 **DeskFox 预览版**),新功能预览;与正式版共享数据 | 主动 opt-in 早鸟用户 / 内部测试 |

## 二、命名空间分离

**两个独立命名空间,token 不撞**:

| 命名空间 | token | 含义 |
|---|---|---|
| Git 分支 | `main` | 本仓主分支(2026-05-21 由 `dev` 重命名)|
| Git 分支 | `feat/<name>` | feat 分支(合 main 即销毁)|
| Git 分支 | `upstream/dev` | 上游 anomalyco/opencode 主分支(他们仍叫 dev)|
| Installer channel | `prod` | Tier 1 稳定版 |
| Installer channel | `beta` | RC 储备(日常不用)|
| Installer channel | `dev` | Tier 2 预览版 / Tier 3 本地测试 共用代号 |

**为什么 Tier 2 / 3 共用 `dev` 代号**:
- Tier 3 不打包(`build-deskfox.ps1 -Env dev -NoBundle` 只出 raw exe),不分配版本号
- Tier 2 才走 installer 流程(`pack-installer.ps1 -Env dev`),版本号带 `-dev` 后缀
- 同一份 raw exe build 出来后,既可以"Tier 3 直接跑"也可以"Tier 2 用 Inno Setup 包成 installer 发预览版" — 区别在**走没走 pack-installer**,不在 build 阶段

## 三、版本号规则(2026-06-05 起 semver 体系;旧 `YYYY.M.D.N` 已废)

> **为什么从 4 段日历号改成 3 段 semver**:启用自动升级(Tauri updater)后,updater 在 **Win/Mac/Linux 三端都用 semver 比较版本新旧**。旧的 4 段号 `2026.6.4.1` 不是合法 semver,updater 无法比较;且 macOS `CFBundleShortVersionString` 只接受 ≤3 段整数。故 2026-06-05 user 拍板改用 3 段 semver。详见 [`feat: 启用自动升级`](../features/启用自动升级/)。

### 3.1 格式:`YYYY.次.补`(合法 semver,3 段纯数字)

```
YYYY.MINOR.PATCH          例:2026.6.0
```

| 段 | 名 | 含义 | 何时 +1 |
|---|---|---|---|
| `YYYY` | 主(year)| 年份 | 跨年自然进位(2026→2027)|
| **次**(MINOR)| 功能波次 | 当年第几波功能 | **大更新**(新功能 / 较大改动)|
| **补**(PATCH)| 修补号 | 该波内的修补 | **小更新**(bugfix / 适配补丁)|

- **起步号 `2026.6.0`**(2026-06-05 user 拍板,接当前"6 月"认知)
- **大更新**:`2026.6.0` → `2026.7.0`(进"次"位,补归零)
- **小更新**:`2026.6.0` → `2026.6.1`(进"补"位)
- 跨年:`2026.12.x` 之后下一波是 `2027.1.0`
- **必须 3 段纯数字**(semver 硬要求);**env 后缀不进 version 本身**(见 3.5)

### 3.2 各端独立计数 + `YYYY.次` 弱协同(2026-06-05 user 拍板)

DeskFox 各平台**发布节奏 / 功能可能不一致**(Linux 滞后、Win 单独打适配补丁 Mac 不需要等),故**每个平台一条独立版本线**,号不必跨平台相同。协同靠一条软约定(业界 Telegram / Obsidian 同模式):

| 场景 | 规则 |
|---|---|
| 同一波功能**同时上多端** | 共用 `YYYY.次` 前缀(Win/Mac 同发功能波 7 → 都 `2026.7.0`),用户一眼看出同批 |
| 某端**单独打补丁** | 只涨该端「补」(Win 适配 bug → `2026.7.1`;Mac 不需要则停 `2026.7.0`)|
| 某端**滞后**(如 Linux)| 按自己节奏走,追上某波时跳到该波号(`2026.7.0`)|

- 版本号标识"**该端某次构建**",**不承诺跨平台功能对等**(行业惯例)
- `YYYY.次` 是"功能波次"的**弱协同信号**(对齐时共享、分叉时各走),`补` 是各端**独立**修补计数
- `installer-versions.json` 里 **windows / macos / linux 各存一个独立 version**

### 3.2bis prod / dev 独立号线 — Dev 领先模式(2026-06-09 user 拍板)

除"各端独立"外,**prod 与 dev 预览版也各走独立号线,互不耦合**(prod ship 不动 dev 号,反之亦然)。`installer-versions.json` 因此是 **channel × platform** 两维:

```json
{
  "windows": "2026.7.0", "macos": "2026.6.0", "linux": "2026.6.0",        // prod 稳定版号线
  "dev-windows": "2026.7.0", "dev-macos": "2026.6.0", "dev-linux": "2026.6.0"  // dev 预览版号线(独立)
}
```

- **扁平复合 key**(`dev-<plat>`)而非嵌套 —— prod 读取(`.macos`)零改动、`grep/sed` 改写不互撞(`"macos"` 不匹配 `"dev-macos"`,后者 `macos` 前是 `-` 非 `"`),Win/Mac 工具链改动面最小。
- 格式同为 `YYYY.次.补` 纯数字(env 不进版本字符串,见 §3.5);渠道靠文件名前缀 / updater 路径 / identifier 区分(已有,见 §3.5 表)。
- **Dev 领先模式**:新功能先进 dev 预览(dev 先 `--bump minor` 领先到下一波),稳定后 prod 才追上同一波次 → 读起来「dev 号 ≥ prod 号,大号=更新的预览」,同 Chrome / VSCode Insiders 惯例。
- **脚本联动**:`bump-installer-version.{sh,ps1} --env dev` / `build-deskfox --env dev` / `pack-installer --env dev` 自动走 `dev-*` key;`--env prod` 走裸 key;复合 key 缺失时 build 兜底回落裸 key。
- **seed(2026-06-09)**:dev-* 初值 = 当前 prod(dev 尚未预览新波次),首次 dev 预览新功能 `--bump minor` 时自然领先。

### 3.3 版本号注入(修复历史 `0.0.0` bug)

**历史问题**:旧 build 链从不注入版本号 → Tauri app 版本回落到 `Cargo.toml` 默认值 `0.0.0`(updater off 时被 Inno `.iss AppVersion` 的外壳号掩盖)。

**2026-06-05 起**:`build-deskfox.ps1` / `build-deskfox.sh` **build 前从 `installer-versions.json` 读对应平台版本号,经 Tauri `--config` 注入**,使 **exe/app 属性、安装包、updater 比较、UI 版本牌报同一个真实版本号**。详 [`feat: 启用自动升级`](../features/启用自动升级/)。

### 3.4 updater 清单按平台分发

endpoint 用 Tauri `{{target}}` 变量,每平台拉各自 `latest.json`:

```
https://updates.deskfox.ai/v1/latest/desktop/{{target}}/latest.json
```

Windows → `windows/`、macOS → `darwin/`、Linux → `linux/`。**各端 manifest 含各自版本号**,互不干扰(Win 补丁不会惊动 Mac 的升级器)。`finalize-latest-json.ts` 按平台分别生成。

### 3.5 env 区分(不进 version 字符串)

version 本身保持纯 semver(`2026.6.0`)。prod / dev / beta 区分通过:

| 维度 | prod | dev(预览)| beta(储备)|
|---|---|---|---|
| installer 文件名前缀 | `DeskFox-` | `DeskFox-Dev-` | `DeskFox-Beta-` |
| updater channel 路径 | `desktop/` | `desktop-dev/` | `desktop-beta/` |
| app identifier | `ai.deskfox.app` | `...app.dev` | `...app.beta` |
| **版本号号线** | 裸 `<plat>` key | 独立 `dev-<plat>` key(§3.2bis)| 独立 `beta-<plat>` key |

> **不用 semver prerelease 后缀(`2026.6.0-dev`)**:虽合法,但 updater 会判 `2026.6.0-dev < 2026.6.0`(prerelease 排序低),且 Mac `CFBundleShortVersionString` 不接受连字符。故 env 一律不进 version。
>
> ⚠️ **prod / dev 不共号**:dev 的版本【数字】走自己独立号线(§3.2bis Dev 领先模式),不是"prod 同号 + 渠道区分"。上表区分的是**渠道身份**(文件名/路径/identifier),版本数字本身由各自号线独立决定。

### 3.6 历史:旧 4 段日历号 `YYYY.M.D.N`(2026-05-21 ~ 2026-06-05,已废)

> 2026-06-05 前 shipped 的版本(`2026.5.21.1` / `2026.6.4.1` / `2026.6.5.1` 等)用旧格式 `YYYY.M.D.N[-env]`,靠 Inno `.iss` ISPP 注入 + `VersionInfoVersion` strip 后缀。**NSIS 切换 + updater 启用后整体废止**。旧安装包用户不受影响(手动升级一次即切到新号线)。旧规则细节(N 序列双维度独立、`VersionInfoVersion` strip、`.iss OutputBaseFilename`)见本文件 git history v1.0。

### 3.7 Beta 版号线(2026-06-14 确认)

beta 与 dev **完全同构**,只是发布列车位置不同:`dev(最前)→ beta(候选 RC)→ prod(最稳)`。

- **独立号线 `beta-<plat>` key**,格式同 `YYYY.次.补` 纯数字,**不加后缀**(同 §3.5 理由)。
- **渠道身份**靠已定的:文件名前缀 `DeskFox-Beta-` / app id `.beta` / updater 路径 `desktop-beta/` / 顶部 `BETA` 徽标(§3.5 表)。
- **号大小关系**:同一波功能 `dev号 ≥ beta号 ≥ prod号`(dev 先试 → beta 转 RC → prod 转正)。
- **储备渠道**:beta 是高风险发版(大重构等)才启用的候选渠道,日常不 ship。`installer-versions.json` **首次发 beta 时才加** `beta-<plat>` key,平时不放(减少维护面)。
- **脚本联动**:`--env beta` 走 `beta-*` key(同 dev 机制),缺失回落裸 key。

### 3.8 Tier 3 本地测试版号(2026-06-14 确认)

本地/自测 raw exe(`build-deskfox --env dev --no-bundle`)**不分配独立发布号**:

- **沿用 dev 线版本号**:Tier 3 本就是 dev 渠道的未打包产物,直接读 `dev-<plat>`(现 = 2026.7.0),**不在 `installer-versions.json` 建专属 key**。
- 业界惯例:本地/CI 构建用 git commit hash 溯源,不占发布号。
- **可选溯源**:本地构建可在 UI 版本牌后挂 git 短 hash(`v2026.7.0 (a1b2c3d)`)便于认构建。Tier 3 **永不分发/升级**,故此 hash 后缀不受 §3.5「version 不加后缀」约束(那是为 updater 比较 + Mac CFBundleShortVersionString,Tier 3 两者都不涉及)。

### 3.9 多架构(arch)规则 —— 同版本号(2026-06-14 user 拍板)

**架构不是版本维度。** 版本号标识"哪次发布",架构标识"在哪种芯片跑",二者正交。**三维度独立、不混入同一字段**:

```
版本号(YYYY.次.补) × 渠道(prod/dev/beta) × 架构(arm64/x64)
```

- **平台 vs 架构两个层级**:**平台**(win/mac/linux)各走独立号线(§3.2,发布节奏不同);**架构**(arm64/x64)在**同一平台内共享同号**(同一次发布的不同芯片构建,不是新版本)。
- **`installer-versions.json` 按"平台+渠道"建 key,不按架构**:mac arm64 与 x64 都读 `macos` / `dev-macos`(同号)。
- **架构只进文件名**:`DeskFox[-Dev|-Beta]-<版本>-<os>-<arch>.<ext>`(electron-builder `artifactName` 已含 `${arch}`)。例:
  - `DeskFox-2026.7.0-mac-arm64.dmg`(M 系列)
  - `DeskFox-2026.7.0-mac-x64.dmg`(Intel)
  - `DeskFox-2026.7.0-win-x64.exe`
- **Mac 出包方式(user 拍板):分架构两个独立包**(arm64 + x64 各一 dmg,同版本号),**不出 universal**——DeskFox 已内置 LibreOffice 体积本大,universal(含两芯片切片)会再翻倍,国内下载成本高;分包每个更小。下载页 / updater 按运行芯片自动递对应包。
- **updater 按 arch 区分**:Mac `darwin` manifest 需 arm64 / x64 各自分发(各自 `latest.json` 或同 manifest 含两 arch 条目),electron-updater 按运行架构拉对应包。**Win 当前只 x64**,暂无此问题(未来出 win-arm64 同理)。

### 3.11 第 4 档 `local` 本地测试版:独立身份 + 数据隔离(2026-06-17 user 拍板)

> **背景**:原先"本机开发自测"复用 dev(预览版)身份(未打包跑硬编码 `ai.deskfox.app.dev` / "DeskFox Dev"),
> 导致 ① 语义混淆(预览版是可对外发布的正式渠道,不该和本地自测同名)② 抢预览版单实例锁 ③ 共用 `opencode.db`
> 污染正式/预览数据,且本地折腾会杀/扰正在用正式版干活的进程。2026-06-17 user 拍板:把本地自测拆成独立第 4 档 `local`。

| 维度 | `local` 本地测试版 | 对比:`dev` 预览版 |
|---|---|---|
| 对外显示名 | **DeskFox 本地版** | **DeskFox 预览版**(原 "DeskFox Dev" 已改) |
| 内部代号 | `local` | `dev` |
| appId | `ai.deskfox.app.local` | `ai.deskfox.app.dev` |
| 数据库 | **`opencode-local.db`(隔离)** | `opencode.db`(与正式版共享,升级无感) |
| 触发方式 | 未打包 `bun run dev:desktop`,或打包 `OPENCODE_CHANNEL=local` | 打包 `OPENCODE_CHANNEL=dev` |
| 发布 / updater | **永不发布**;无 `publish`、无自动升级 | 公开预览(prerelease) |
| 版本号 | 不分配号线,回落平台裸号 | 独立 `dev-<plat>` 号线(§3.2bis) |

- **数据隔离机制**:`server.ts` `createSidecarEnv` 仅对发布三档设 `OPENCODE_DISABLE_CHANNEL_DB=1`(统一 `opencode.db`、升级无感);对 local 身份(未打包 / `CHANNEL==="local"`)改为显式 `OPENCODE_CHANNEL=local` → sidecar 落 `opencode-local.db`,与正式版 `opencode.db` 物理隔离。本机灌测试数据、折腾本地版,绝不污染正式/预览数据,也不会因共享 DB 互踩。
- **进程隔离**:appId 独立 → 单实例锁不与正式版(`ai.deskfox.app`)/ 预览版(`...app.dev`)相撞,**可与正式版同时运行**(边用正式版干活、边跑本地版测试)。注:未打包 `bun run dev:desktop` 与"打包出的 local 版"同为 `ai.deskfox.app.local` 身份,二者不要同时跑。
- **预览版正名(同笔)**:dev 渠道对外**显示名** "DeskFox Dev" → **"DeskFox 预览版"**(`PRODUCT_NAMES.dev`,constants.ts / electron-builder.deskfox.config.ts 两处单一源);**内部代号、产物文件名前缀(`DeskFox-Dev-`)、updater 路径(`desktop-dev`)、appId(`.dev`)一律不动**,发布链零影响(§3.5 渠道身份不变)。
- **代码触点**:`constants.ts`(Channel 加 local + PRODUCT_NAMES + UPDATER_ENABLED)/ `index.ts`(APP_IDS + 未打包身份)/ `server.ts`(DB 归属分流)/ `electron.vite.config.ts`(channel 透传 local,否则被兜底成 dev)/ `electron-builder.deskfox.config.ts`(APP_IDS/PRODUCT_NAMES/ARTIFACT_PREFIX/`publish=null`)/ `titlebar.tsx`(LOCAL 徽标)/ `migrate.ts`·`deskfox/telemetry.ts`(身份兜底)。[feat: local-channel] 2026-06-17

### 4.3 Tier 3 — 本地测试版(`local` 独立渠道,**永不发布**)

> 2026-06-17 起本地测试版是独立 `local` 渠道(原先与 dev 共代号 + `--no-bundle`)。完整身份/隔离规则见 **§3.11**。

| 项 | 规则 |
|---|---|
| 内部代号 / appId | `local` / `ai.deskfox.app.local`(独立,与正式版/预览版均不撞,可同机共存)|
| 系统显示名 | `DeskFox 本地版`(顶部 `LOCAL` 徽标)|
| 数据库 | **`opencode-local.db`(与正式版 `opencode.db` 隔离)**——本机灌测试数据不污染正式/预览数据 |
| 操作命令(热重载自测)| `bun run dev:desktop`(未打包,改码即时见效;身份即 local)|
| 操作命令(打包独立 .app)| `OPENCODE_CHANNEL=local bunx electron-builder --mac --dir --config electron-builder.deskfox.config.ts`(`--dir` = 不出 dmg/installer 的可直接跑 .app;Win 用 `--win`)|
| 版本号 | **不分配号线**,回落平台裸号(`installer-versions.json` 的 `<plat>` key)|

| publish / 自动升级 | ❌ 无 publish 源、无 updater(§3.11)|

## 五、操作 SOP

> **2026-05-21 起 ship 流程全本地化**:user 决议放弃 GitHub Actions cloud build,3 个 release workflow yml 永久废止(`release-deskfox.yml` / `release-mac-deskfox.yml` / `release-mirror-gitee-deskfox.yml`)。原因:Win runner 撞 sidecar deadlock + Gitee mirror silent fail 双坑,本地 ship 流程已实战跑顺。

### 5.1 出 Tier 1 稳定版(每次必 bump,要发布)

```powershell
# 1. 本地 pack(bump + build + ISCC pack 一条龙)
.\packages\branding\scripts\pack-installer.ps1 -Env prod    # Windows
bash packages/branding/scripts/pack-installer.sh --env prod  # Mac

# 2. 提交 bump artifacts
git add packages/branding/installer/DeskFox.iss packages/branding/installer-versions.json docs/installer-versions.md
git commit -m "chore(ship): bump prod 2026.5.21.1 — <一句话总结> [feat: <相关-feat-id>]"
git push origin main

# 3. 推 tag
git tag ship-prod-2026.5.21.1   # Mac 端用 ship-mac-prod-<版本>
git push origin ship-prod-2026.5.21.1

# 4. 创建 GitHub Release(本地手动,Tier 1 用 latest 标)
gh release create ship-prod-2026.5.21.1 \
  packages/branding/installer/Output/DeskFox-2026.5.21.1-setup.exe \
  --title "DeskFox 2026.5.21.1" \
  --notes "<release notes>"

# 5. 镜像 Gitee — 元数据 + 附件
$body = @{
  access_token = $env:GITEE_TOKEN
  tag_name = "ship-prod-2026.5.21.1"
  name = "DeskFox 2026.5.21.1"
  body = "<同 GitHub Release body>"
  target_commitish = "main"
} | ConvertTo-Json
Invoke-RestMethod -Uri "https://gitee.com/api/v5/repos/zoulukuang/deskfox/releases" -Method POST -Body $body -ContentType "application/json;charset=UTF-8"

.\packages\branding\scripts\mirror-asset-to-gitee.ps1 -Tag ship-prod-2026.5.21.1
```

### 5.2 出 Tier 2 预览版(每次必 bump,要发布)

跟 Tier 1 几乎相同,差别只在:
- `pack-installer.ps1 -Env dev`(dev env)
- `gh release create ... --prerelease`(prerelease 标)
- Gitee API body 加 `prerelease = $true`
- tag 用 `ship-dev-<版本>-dev`(含 B2 后缀)

```powershell
# 1. 本地 pack
.\packages\branding\scripts\pack-installer.ps1 -Env dev

# 2. 提交 bump + push

git push origin main
git tag ship-dev-2026.5.21.1-dev
git push origin ship-dev-2026.5.21.1-dev

# 3. GitHub Release(prerelease)
gh release create ship-dev-2026.5.21.1-dev \
  packages/branding/installer/Output/DeskFox-Dev-2026.5.21.1-setup.exe \
  --prerelease \
  --title "DeskFox Dev 2026.5.21.1-dev (预览版)" \
  --notes "<release notes>"

# 4. Gitee 元数据 + 附件
$body = @{
  access_token = $env:GITEE_TOKEN
  tag_name = "ship-dev-2026.5.21.1-dev"
  name = "DeskFox Dev 2026.5.21.1-dev (预览版)"
  body = "<同 GitHub Release body>"
  prerelease = $true
  target_commitish = "main"
} | ConvertTo-Json
Invoke-RestMethod -Uri "https://gitee.com/api/v5/repos/zoulukuang/deskfox/releases" -Method POST -Body $body -ContentType "application/json;charset=UTF-8"

.\packages\branding\scripts\mirror-asset-to-gitee.ps1 -Tag ship-dev-2026.5.21.1-dev
```
