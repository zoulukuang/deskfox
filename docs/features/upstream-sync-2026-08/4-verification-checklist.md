## 一、方法论(先定方法,方法决定结果)

### 1.1 清单怎么保证「全」

| 原则 | 含义 |
|---|---|
| **可枚举优先于可回忆** | 凡机器能列的一律机器列(命令注册表 / 快捷键 / 菜单树 / 设置页 / DOM aria-label / FORK feat-id),不靠人想 |
| **多源交叉,互相补漏** | 单一来源必有系统盲区,取并集:**入口源**(能点到什么)+ **定制源**(改过什么)+ **风险源**(修过什么)+ **能力源**(产品命脉) |
| **以「用户能做的动作」为单元** | 不以代码模块为单元 —— 验收方式是亲手操作。「session-side-panel.tsx」不是条目,「tab 右键→关闭其他标签」才是 |
| **每条必带可判定对照** | 固定格式「动作 → 基准版表现 / 当前版表现 / 是否一致」。没有基准列的条目不算数,那等于退回拍脑袋 |

**自检环节(必做)**:清单初稿完成后反问「哪些来源没跑?哪个盲区没覆盖?」
—— 本清单初稿 28 项,自检后补到 **63 项**,翻了一倍多,证明自检不是形式。

### 1.2 验证怎么保证「真」

三条硬规矩,都是踩坑换来的:

1. **真实输入,不用合成事件**。`element.click()` / `new KeyboardEvent()` 触发不了 SolidJS handler,
   必须用 CDP `Input.dispatchMouseEvent` / `dispatchKeyEvent`。
   (2026-08-13 踩坑:用 JS click 验证侧栏 toggle,得出「仍然失效」的错误结论,差点二次误判。)
2. **可靠指标,不用文案判定**。`innerText.includes("新建会话")` 这类判定会被其他区域的同名文案污染,
   要读驱动该行为的**变量本身**(如 `--main-right`)或做**像素级确认**。
3. **视觉改动必须像素级验收**。读 computed style 只能证明「样式挂上了」,不能证明「用户看得见」。
   (2026-08-13 踩坑:分隔线 computed style 显示 1px solid,实际被子元素覆盖、放大 8 倍截图后是纯白。)

### 1.3 修改怎么保证「不反复」

1. **发现有害 pattern → 全仓 grep 同类,逐个评估**,不能只改复现路径那一处。
   (row-reverse 修了又复发,就是只改了触发点。)
2. **新增功能必须回归它影响的既有交互**。
   (自动收起劫持了侧栏手动 toggle;8 条单测全绿却没抓到,因为测的是纯函数、bug 在接线时序。)
3. **渲染条件依赖桌面环境的约束,e2e 抓不到,必须上源码级静态守卫**。
   (`SessionSidePanel` 外层 `Show when={isDesktop()}`,web e2e 整棵子树不渲染,断言必然空过。)
4. 守卫要做**反向验证** —— 故意注入违规,确认它会红。不做反向验证的守卫可能是装饰品。

### 本轮修掉的真缺陷:文件树点**文件**后焦点丢失(commit `1f458b9cbc`)

按 #40 逐项验时实测发现:点**目录**行焦点正常落入文件树,点**文件**行则回到 `body`,
文件树键盘作用域随之失效。根因不是「没设焦点」——`aaea87be98` 那笔确实设了 ——
而是设完之后行被**重挂**:文件被打开 → 该行成为 active 且预览区已开 →
命中 `inactive={!(local.viewerOpen && local.node.path === local.active)}` 的 Tooltip 包裹分支,
DOM 节点销毁重建(实测「旧节点还在文档里 = false」),焦点掉回 body。
目录行永远不会成为 active,所以不触发 —— 这就是当初「只修好一半」的由来。

修法:fork-only 纯函数 `restoreRowFocus`,在 `requestAnimationFrame` 里排到重挂之后补焦点;
**只在焦点确实掉回 body 时才补**,用户主动点别处不抢回来。4 条单测(含 2 条反向)+ 真机双向验;
app 包单测对照 870→874 pass,12 项失败前后一致(既有基线红)。

### ✅ 已收口:上游带进来的 3 项单测红(2026-08-14 发现,同日修复)

推分支给 Win 端时被 `pre-push` 闸拦下,查明:

- 失败项:`packages/app/src/context/server-session.test.ts` 的 3 条
  (`projects V2 session events…` / `indexes V1 messages…` / `does not scan cached messages…`)
- **不是本轮工作引入的**:回退到 `5d2e316801`(本会话动手前)实测同样红。

**性质判断(证据链,全部实测)**:**不是产品缺陷** ——

1. **内容完全一致**:同一个值 JSON 解包后,同样的 `toMatchObject` 直接通过;
2. **换个匹配器就过**:`toEqual` 对同一个 store 数组通过;单个元素的 `toMatchObject` 也通过。

  堆栈显示触发点是**断言那一行自己** —— `toEqual` 深比对会读遍所有属性,
  store 为真 proxy 时把读透传到测试自己布的陷阱上。守卫本意是「**loadMore 期间**

### 顺带查出:含反斜杠文件名时,「四通道写法一致」这个不变式在 POSIX 上反过来

`\` 在 macOS/Linux 上是**合法文件名字符**。实测 `toMentionSeparators("docs/a\\b.md")`
→ `"docs/a/b.md"`,即一个真名叫 `a\b.md` 的文件,@ 路径被写成一个**不存在的嵌套路径**。

四条通道的实际行为(已逐条查源):

| 通道 | 含 `\` 文件名时 |
|---|---|
| `@` 提及补全(搜索结果) | `docs/a\b.md` ✅ **唯一给对的** |
| `@` 提及补全(recent/已开标签) | `docs/a/b.md` ❌(`encodeFilePath` 先替换再分段) |
| 文件树拖入(单选 / 多选) | `docs/a/b.md` ❌ |
| 外部拖入 | `docs/a/b.md` ❌ |

**定性**:① **不是 Win 那笔改动引入的** —— 四条里三条早就如此,它只是把第 4 条纳入同一行为,
就「消除写法分裂」这个目标而言改法本身没错;② **不是本次同步的回归**,基准版同样如此;
③ 影响面很小(macOS 上文件名带 `\` 极罕见),但真触发时是**静默指向错文件**。

**正解方向**:归一化应按平台开闸 —— Windows 上 `\` 不可能出现在文件名里,替换安全;
POSIX 上 `\` 是普通字符,不该翻译。**本轮不改**:它与 sync 无关、且属既有行为,
临近合 main 不宜扩面。已记入需求池待排期。
