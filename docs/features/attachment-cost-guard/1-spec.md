# 附件成本保护施工规格

绑定 REQ-142/143/144；计划为 OPENCODE-PLAN/需求计划/2026-10-12.md。本规格仅成本组，分享组另行处理。2026-10-12 已获准执行 C0 调查和准备；本稿基于实际测试，待 Large 规格审签后进入 C1-C3 产品实现。

## 规模与落地顺序

预计整体 700–1200 行，触及 prompt/read、attachments/submit、session 状态 UI、i18n 等至少 5 个上游文件，按 Large 管理。先 C1 服务端封顶，再 C2 三入口路由，最后 C3 发送前和轮后提醒；完成 C4 后才提合并。C0 探针为独立验证工作，尚未更改产品行为。

## C0 已验证事实

1. legacy 新消息携带 864000 字节 CSV，持久消息有一份等长 synthetic；本地假模型捕获两轮请求，每轮均含完整 CSV。
2. V2 toLLMMessages 保留等价媒体 URI，OpenAI Chat prepare 明确拒绝 text/plain，没有网络发送。不能声称 V2 已发生同样的全文计费，也不能借本批新增 V2 附件解析产品能力。
3. legacy read 的 3000 行/6000 字节文本仅展示 2000 行；100100 字节文本显示前 51 行并指向 offset=52；60000 字节单行被裁到 2000 字符并附 suffix。包装后的输出可超过 51200 字节。
4. V2 read 的相同 3000 行小文件完整返回；PDF 返回 BinaryFileError。两代 read 不强行统一运行行为。
5. MIME 识别将 CSV/空 MIME 文本归为 text/plain，PDF 保留 application/pdf，Office 二进制拒绝；现有外拖却把有路径 PDF/Office 都转 path。

测试基线是 `b2162c0c7dc77700d718aa43ecbf8a080466565b`；数值为合成样本，不是用户数据。全量证据见 3-changelog。

## C1 服务端限额

- legacy data:text/plain 解码后的附件正文最多 51200 UTF-8 字节、2000 行，单行上限对齐 legacy read 的 2000 UTF-16 字符，截断必须保留完整 Unicode 字符。先裁行，再按整行字节预算收集，固定 suffix 计入正文预算。
- 提取无 IO 的轻量规则模块供 legacy prompt/read 共用；不把 Core 服务引入浏览器，不修改 V2 read 小文件语义。保留小文本内容与原附件 UI 展示。
- 正文、工具包装和固定提示分别验；无路径用固定无续读指令提示。即使 filename 是绝对路径，未经同执行 Location 验证也不建议 offset 读取。
- 长单行裁掉中段时明确说明不能用下一行 offset 找回。行数/字节先触限的下一行号对应原文；不固定写 offset=2001。
- 新生成 synthetic 增加服务端来源标记，为后续只读模型投影保护提供依据。不因客户端提供 synthetic=true 就截正文。
- **旧历史不做自动启发式改写/截断**：当前历史没有可靠强关联。C0 证明原消息会继续重放；修复承诺仅为新附件准入。发行说明提示大附件旧会话新开或显式压缩，不能称历史已修。将来可靠来源迁移另定，不以全文相等猜用户正文来源。
- 本批不新增 V2 文本媒体支持；保留其已验证拒绝行为。V2 原生 synthetic/用户正文不按 legacy 附件猜测截断。
- 单附件限额不等于请求总 token 限额；多个附件仍累计。非法编码应得到可见错误；不把全文解码后截断称为 HTTP/OOM 防护。

## C2 附件入口

三入口统一使用 attachmentMime 规范化结果。文本且执行侧路径可用→引用；图片/PDF→合法内联；无路径文本→内联；不支持二进制→明确拒绝。外部拖入 PDF/Office 的现有错误路由需要修正，不改变内部文件树/@ 补全。

自动引用仅在已证明桌面内置 base sidecar 与本机文件系统一致时启用；不能用 localhost 推断（可能为端口转发），WSL/SSH/自定义远端默认保留合法内联。使用现有连接身份，不新设任意路径探测 API。路径权限仍由执行侧现有 Read 检查。

引用在建立 blob 前插入捕获的草稿和光标。异步 MIME 检测期间切会话不能写错草稿；混合多选顺序稳定、每份只插一次，失败保留已成功附件。路径发送前失效则明确错误，不偷偷恢复别的文件。

## C3 提示与确认

建议默认 `>=200KiB` 弹发送确认；不加设置项、不显示未经 tokenizer 验证的 token 数。显示原始附件体积、预计送模文本范围及成本风险；二进制只显示字节和风险。旧后端保护能力未知时按原始量提示；已路径化文本不计内联。

确认在历史记录、worktree/session.create、乐观消息及任何发送副作用之前；支持取消/继续，仅满足 C2 可读条件的文本提供转换。锁住提交快照，草稿/连接/模型变化使原确认失效；覆盖普通 prompt 与 /command 附件入口。取消保留全部草稿，零创建/发送请求，重复点击只提交一次。

轮后输入统计取 `input+cache.read+cache.write`。按同一用户输入轮最后一条已完成 assistant 统计，建议 `增量>=100000 && 新值>=旧值*3`；旧值缺失/零不判。去重键为 server scope/session/user message，处理 idle/token 事件乱序。初载历史只建基线；切模型/压缩/revert 重新建基线。提示复用新会话/显式压缩操作，不自动执行。
