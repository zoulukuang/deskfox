# 冻结(让后端不再响应,但连接还在 —— 这才是"半死";kill 掉是"已死",走的是另一条错误路径)
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -STOP

> 解冻后回 `S` —— 同时正式版的对应进程路径是 `DeskFox Helper`(无「本地版」),**不在匹配范围内**。

## ~~P0-1 送达超时(120s)~~ —— **已撤销,前提不可达**(2026-09-19 实测)

原计划让 user 冻结后端、等满 120 秒触发 `PROMPT_DELIVERY_TIMEOUT_MS`。**做不到**,两道原因:

1. **看门狗先动手**:`sidecar-watchdog.ts` 每 5s ping `/global/health`,连续 3 次失败即判定死亡
   并同 port 重启。实测冻结只维持 **37~41 秒**(15:25:35 冻 → 15:26:13 新后端接管;
   15:44:30 冻 → 15:45:11 接管)。120 秒的线**永远等不到**。
2. 要强行撑住窗口,得每秒把看门狗重启出来的新进程再冻掉(本轮为测停止键确实这么做了,
   见 `hold-freeze.sh` 思路),但那会把看门狗逼进熔断(120s 内 5 次 → gave-up),
   属于人为制造的极端态,不是用户会遇到的形态。

**结论**:REQ-100 ④ 的 120s 送达超时是「**看门狗也救不回来时的最后兜底**」,
日常路径轮不到它。它的逻辑由 `submit-delivery.test.ts` 的单测覆盖(可注入 `deliveryTimeoutMs`)。

**但这一轮仍验到了有效结果**(user 实测,2026-09-19 15:25):
后端冻结期间在**新会话**里发送(带一张引用卡 + 一句可识别原文)——
- 提示:「创建会话失败 / Failed to fetch」+「发送提示失败 / 无法获取会话」
- **输入框里的原文和那张引用卡都还在** → **没有静默蒸发** ✅

> 📌 顺带记一个瑕疵(非本批引入):`Failed to fetch` 是浏览器原生英文串,直接透给了用户。

## P0-2 停止键:后端不响应时也能停下来(REQ-100 ①)

**为什么只能人工**:要在「后端半死」窗口里点停止键。

⚠️ 本轮修的那个**完整形态**(会话被 LRU 挤出 → 反向对账永久跳过它)**人工也造不出来** ——
`sessionInfoLimit = 2_048`,要挤掉一个会话得先加载过 2000+ 个会话。
所以这条测的是**相邻的主路径**(停止兜底 → 对账把状态盖回来),完整形态由
`global-sync/stale-busy.test.ts` 的两段式闭环覆盖。

**操作步骤**

1. 新建会话,粘贴这句并发送(挑个会输出一会儿的任务):

   ```
   验收用例 B —— 请用不少于 800 字,分点讲清楚这个项目的目录结构和每个目录的职责。
   ```

2. 等它**开始输出**(看到文字在往外冒)
3. 终端执行**冻结**(命令同上)
4. 回到 DeskFox,**点停止按钮**
5. 盯着看约 **4~5 秒**

**预期(第一半)**

- 约 4 秒后转圈停下、会话显示空闲、停止按钮变回发送按钮
- 这是前端兜底:后端其实还被冻着,但界面不该一直卡着转

6. 终端执行**解冻**(命令同上)
7. 再等最多 **60 秒**(周期对账一轮)

**预期(第二半)**

- 如果那一轮后端其实还在继续跑 → 界面应当**自己把「运行中」恢复回来**,并最终出结果
- 如果后端那轮已经结束 → 正常收尾,不残留转圈

**失败长什么样**

- 点了停止,转圈一直不停(超过 10 秒还在转)→ 兜底没生效
- 解冻后界面一直显示空闲,但你发下一条消息,回复里**夹着上一轮的内容** → 两轮并发(对账没盖回来)
- 或者反过来:永远转圈停不下来(幻影 busy)

**收尾**:确认已解冻。

### ✅ 验收结果(user 实测,2026-09-19 15:55~15:58)

冻结用的是**持续冻结**(每秒把看门狗重启出来的新后端再冻掉,共拦截 3 次重启:
15:55:08 / 15:55:45 / 15:57:02),以消除时间压力。user 观察到的是一条**完整咬合的链**:

| 现象 | 对应代码 |
|---|---|
| 输出中断在半句 | 后端被冻结 |

| 约 4 秒后停止按钮变回发送键 | `STOP_FALLBACK_IDLE_MS` 本地兜底(REQ-100 ①)—— 按钮不永久转圈 |

三条提示**全中文、口径一致、无英文内部串、无静默失败**。对照修复前形态
(点停止没任何反馈、转圈永不停),本批核心收益成立。**判定:通过。**
