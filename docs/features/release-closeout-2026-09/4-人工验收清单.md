- 本轮启动用的是**临时配置目录**(从 local 配置拷来、摘掉了 `feishu-bridge` plugin),

**一条你会反复用到的命令**——冻结 / 解冻本地版的后端(测「后端半死」必需):

```bash
# 冻结(让后端不再响应,但连接还在 —— 这才是"半死";kill 掉是"已死",走的是另一条错误路径)
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -STOP

# 解冻(每条测完务必执行,否则本地版一直卡着)
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -CONT
```

> 为什么是这个进程:本地版的后端**跑在 Electron 的 Node utility 进程里**(不是独立的
> `opencode-cli`),所以要冻的是它。上面的 pattern 只匹配**本地版**,不会动到你的正式版。
>
> **已实测**(2026-09-19):pattern 只匹配到 1 个进程(本地版后端);冻结后 `ps -o stat` = `T`(stopped),
> 解冻后回 `S` —— 同时正式版的对应进程路径是 `DeskFox Helper`(无「本地版」),**不在匹配范围内**。

## P0-1 队列路径的「未送达」提示(第四轮 ③)

**为什么只能人工**:触发要后端挂起满 **120 秒**(`PROMPT_DELIVERY_TIMEOUT_MS`),
且同时要会话处于 busy 让消息进队列。代码里的 `deliveryTimeoutMs` 注入口只是**单测 seam**,
e2e 拿不到 —— 自动化版会变成一条 2 分钟的测试,不值。

**步骤**

1. 在本地版里发一条会跑一会儿的问题(比如「把这个仓库的架构讲详细点」),等它**开始输出**
2. 终端执行**冻结**命令(见上)
3. 回到 DeskFox,在输入框再发一条任意消息 —— 此时会话仍显示忙,这条会**进队列**
4. **等满 2 分钟**(可以去干别的)
5. 看弹出的红色提示

**预期**

- 标题:**「这条可能没发出去,仍留在队列里」**
- 正文:「后台引擎 2 分钟内没有响应。这条仍在队列里、已标记为失败,可以重发 —— 重发前请先看一眼对话里是否已经有了。」

**失败长什么样**(任一出现就是回归,把截图给我)

- 标题写成「这条可能没发出去,**已放回输入框**」← 这正是本轮修的那条:标题与正文互相矛盾,
  用户照标题去输入框找原文,那里是空的
- 或者提示是一串英文内部串(`prompt not delivered: backend did not respond in time`)

**收尾**:执行解冻命令。

## P0-2 停止键 + 忙闲对账(第四轮 ② 的可达部分)

**为什么只能人工**:要在「后端半死」窗口里点停止键。

⚠️ **先说清楚**:本轮修的那个**完整形态**(会话被 LRU 挤出 → 反向对账永久跳过它)
**人工也造不出来** —— `sessionInfoLimit = 2_048`,要挤掉一个会话得先加载过 2000+ 个会话。
所以这条测的是**相邻的主路径**(停止兜底 → 对账把状态盖回来),完整形态由
`global-sync/stale-busy.test.ts` 的两段式闭环覆盖。

**步骤**

1. 发一条会跑一会儿的问题,等它开始输出
2. 终端**冻结**后端
3. 在 DeskFox 里点**停止**按钮
4. 观察:约 4 秒后转圈停下、会话显示空闲(这是前端兜底,后端其实还被冻着)
5. 终端**解冻**后端
6. 等最多 60 秒(周期对账一轮)

**预期**

- 解冻后,如果那一轮后端其实还在跑 → 界面应当**自己把「运行中」恢复回来**,而不是一直显示空闲
- 如果后端已经结束 → 正常收尾出结果,不残留转圈

**失败长什么样**

- 解冻后一直显示空闲,但你发下一条消息时,回复里夹着上一轮的内容(= 两轮并发)
- 或者反过来:永远转圈停不下来(幻影 busy)

**收尾**:确认已解冻。

## P1-1 引用卡在真实内容下的观感

**为什么只能人工**:自动化跑在 mock 的小文件上,真实工作区的长路径 / 多卡 / 中文 IME 都没覆盖。

**步骤 + 预期**(在你自己的项目里做)

| 做什么 | 预期 |
|---|---|
| 在一个**路径很长**的 .md 里选一段 → 右键 →「添加到聊天窗口」→ 填注释 → Enter | 卡片出现,文件名截断合理、不撑破输入区 |
| 连续加 **5 张以上**卡 | 自动换行,超过约 3 行时卡片区内部滚动,**不挤压聊天区** |
| 鼠标悬停在卡片上 | tooltip 显示**引文原文**(不是只显示路径) |
| 点卡片右上角 ✕ | 卡片消失;全删光后发送键变灰 |
| 浮层里用**中文输入法**打字,拼音未上屏时按 Enter | **不应提前提交**(应当是上屏),再按一次 Enter 才提交 |
| 不填注释直接 Enter | 也要落卡(卡上没有注释行) |

**失败长什么样**:卡片把输入框撑到看不见聊天;tooltip 只有路径;中文拼音中途被提交。

## P1-2 非 markdown 文件的「选中 → 右键 → 加入聊天」

**为什么只能人工**:自动化只覆盖了 `.md`(light DOM)与 `.txt`(shadow DOM)两类;
真产物里 PDF / Word / Excel 走的是另一套查看器(DocumentViewer / 表格视图)。

在你的项目里各试一个:**代码文件**(.ts/.py)、**PDF**、**.docx**、**.csv**

- 预期:都能选中文字 → 右键出「添加到聊天窗口」→ 填注释 → 落卡
- 失败长什么样:右键没菜单 / 菜单项是灰的 / 落卡后卡片内容是空的

> PDF 有一条已知限制:**跨页选区不支持**,菜单会灰掉并提示「请分段选中后再加入聊天」——
> 这是既有设计,不算 bug。
