```
/Volumes/ExtSSD/opencode-fork/packages/desktop/dist-deskfox/mac-arm64/DeskFox 本地版.app
```

- 它是**本地版**(appId `ai.deskfox.app.local`,`LOCAL` 徽标),与你正在用的正式版**并存**,
  数据隔离(`opencode-local.db`),不会碰你的正式版会话。
- 本轮启动用的是**临时配置目录**(从 local 配置拷来、摘掉了 `feishu-bridge` plugin),
  目的是避免测试实例抢你真实飞书桥的消息路由。要用你平时的 local 配置重启,说一声。

**一条你会反复用到的命令**——冻结 / 解冻本地版的后端(测「后端半死」必需):

```bash
# 冻结(让后端不再响应,但连接还在 —— 这才是"半死";kill 掉是"已死",走的是另一条错误路径)
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -STOP

# 解冻(每条测完务必执行,否则本地版一直卡着)
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -CONT
```

> 为什么是这个进程:本地版的后端**跑在 Electron 的 Node utility 进程里**(不是独立的
> `opencode-cli`),所以要冻的是它。上面的 pattern 只匹配**本地版**,不会动到你的正式版。
>
> **已实测**(2026-09-19):pattern 只匹配到 1 个进程(本地版后端);冻结后 `ps -o stat` = `T`(stopped),
> 解冻后回 `S` —— 同时正式版的对应进程路径是 `DeskFox Helper`(无「本地版」),**不在匹配范围内**。

## P0-1 送达超时:消息不会静默蒸发(REQ-100 ④ 主路径)

**为什么只能人工**:要后端挂起满 **120 秒**(`PROMPT_DELIVERY_TIMEOUT_MS`)。
代码里的 `deliveryTimeoutMs` 只是单测注入口,e2e 拿不到 —— 自动化版会变成一条 2 分钟的测试,不值。

**这条测的是什么**:后端半死时,你发出去的消息**不能就这么没了**。
修复前的形态是:请求既不 resolve 也不 reject → catch 永远等不到 → 输入框已被清空、转圈永不停,
原文连同引用卡**人间蒸发**。

**操作步骤**(照抄即可)

1. 在本地版里**新建一个会话**(右侧栏「新建会话」),确认它**空闲**(不是在跑任务)
2. 在文件树里随便打开一个 `.md`,选中一段文字 → 右键 →「添加到聊天窗口」→ 注释填 `验收测试` → Enter
   → 确认输入框上方出现**一张引用卡**
3. 在输入框里粘贴这句(便于你一眼认出原文有没有回来):

   ```
   验收用例 A —— 这句话必须在两分钟后原样回到输入框
   ```

4. 打开终端,执行**冻结**:

   ```bash
   pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -STOP
   ```

5. 回到 DeskFox,**点发送**(或按 Enter)。此时输入框会被清空、开始转圈 —— 这是正常的乐观表现
6. **等满 2 分钟**(可以去干别的,到点回来看)

**预期**

- 弹出红色提示,标题:**「这条可能没发出去,已放回输入框」**
- 正文:「后台引擎 2 分钟内没有响应。原文和引用卡片都还在。重发前请先看一眼对话里是否已经有了 —— 极少数情况下后台其实已经收下。」
- **输入框里那句「验收用例 A ——…」原样回来了,那张引用卡也回来了**
- 转圈停止,会话回到可输入状态

**失败长什么样**(任一出现就是回归,截图给我)

- 等了 2 分钟没有任何提示,转圈一直转 → 送达超时闸没生效
- 有提示但**输入框是空的** / 引用卡没回来 → 回吐路径坏了(消息真蒸发了)
- 提示是一串英文内部串(`prompt not delivered: backend did not respond in time`)

**收尾**:执行解冻

```bash
pgrep -f "DeskFox 本地版 Helper.*node.mojom.NodeService" | xargs kill -CONT
```

## P0-2 停止键:后端不响应时也能停下来(REQ-100 ①)

**为什么只能人工**:要在「后端半死」窗口里点停止键。

⚠️ 本轮修的那个**完整形态**(会话被 LRU 挤出 → 反向对账永久跳过它)**人工也造不出来** ——
`sessionInfoLimit = 2_048`,要挤掉一个会话得先加载过 2000+ 个会话。
所以这条测的是**相邻的主路径**(停止兜底 → 对账把状态盖回来),完整形态由
`global-sync/stale-busy.test.ts` 的两段式闭环覆盖。

**操作步骤**

1. 新建会话,粘贴这句并发送(挑个会输出一会儿的任务):

   ```
   验收用例 B —— 请用不少于 800 字,分点讲清楚这个项目的目录结构和每个目录的职责。
   ```

2. 等它**开始输出**(看到文字在往外冒)
3. 终端执行**冻结**(命令同上)
4. 回到 DeskFox,**点停止按钮**
5. 盯着看约 **4~5 秒**

**预期(第一半)**

- 约 4 秒后转圈停下、会话显示空闲、停止按钮变回发送按钮
- 这是前端兜底:后端其实还被冻着,但界面不该一直卡着转

6. 终端执行**解冻**(命令同上)
7. 再等最多 **60 秒**(周期对账一轮)

**预期(第二半)**

- 如果那一轮后端其实还在继续跑 → 界面应当**自己把「运行中」恢复回来**,并最终出结果
- 如果后端那轮已经结束 → 正常收尾,不残留转圈

**失败长什么样**

- 点了停止,转圈一直不停(超过 10 秒还在转)→ 兜底没生效
- 解冻后界面一直显示空闲,但你发下一条消息,回复里**夹着上一轮的内容** → 两轮并发(对账没盖回来)
- 或者反过来:永远转圈停不下来(幻影 busy)

**收尾**:确认已解冻。

## P1-1 引用卡在真实内容下的观感

**为什么只能人工**:自动化跑在 mock 的小文件上,真实工作区的长路径 / 多卡 / 中文 IME 都没覆盖。

**步骤 + 预期**(在你自己的项目里做)

| 做什么 | 预期 |
|---|---|
| 在一个**路径很长**的 .md 里选一段 → 右键 →「添加到聊天窗口」→ 填注释 → Enter | 卡片出现,文件名截断合理、不撑破输入区 |
| 连续加 **5 张以上**卡 | 自动换行,超过约 3 行时卡片区内部滚动,**不挤压聊天区** |
| 鼠标悬停在卡片上 | tooltip 显示**引文原文**(不是只显示路径) |
| 点卡片右上角 ✕ | 卡片消失;全删光后发送键变灰 |
| 浮层里用**中文输入法**打字,拼音未上屏时按 Enter | **不应提前提交**(应当是上屏),再按一次 Enter 才提交 |
| 不填注释直接 Enter | 也要落卡(卡上没有注释行) |

**失败长什么样**:卡片把输入框撑到看不见聊天;tooltip 只有路径;中文拼音中途被提交。

## P1-2 非 markdown 文件的「选中 → 右键 → 加入聊天」

**为什么只能人工**:自动化只覆盖了 `.md`(light DOM)与 `.txt`(shadow DOM)两类;
真产物里 PDF / Word / Excel 走的是另一套查看器(DocumentViewer / 表格视图)。

在你的项目里各试一个:**代码文件**(.ts/.py)、**PDF**、**.docx**、**.csv**

- 预期:都能选中文字 → 右键出「添加到聊天窗口」→ 填注释 → 落卡
- 失败长什么样:右键没菜单 / 菜单项是灰的 / 落卡后卡片内容是空的

> PDF 有一条已知限制:**跨页选区不支持**,菜单会灰掉并提示「请分段选中后再加入聊天」——
> 这是既有设计,不算 bug。
