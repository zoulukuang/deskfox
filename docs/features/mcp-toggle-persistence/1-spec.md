# REQ-153 MCP 开关意图持久化

2026-11-14 用户确认日常使用六项迭代并授权开工。分支 `fix/mcp-toggle-persistence`，基线 `fc96b0b5b5`。Medium，预计代码与测试 < 500 行、4 个上游文件；黑名单提交前另行 R4 复核。

## 目标与边界

主动关闭后，刷新、切会话、切项目后返回、实例重建与重启均不自动开启；手动开启才恢复。网络或认证失败不能当作主动禁用。一次项目内操作不能无提示扩大到其他项目。

实施前明确全局/项目配置来源、同名覆盖及只读配置的处理。配置写入失败必须反馈；保留原连接参数及无关设置。多个窗口与迟到连接回调应服从同一份最新意图。使用隔离配置和 MCP fixture，不操作用户真实配置。

## 实施契约与 R1/R4

1. **作用域**：当前后台实例的规范化目录（真实 project/worktree 目录）内，写 `.opencode/opencode.jsonc` 的 `mcp.<name>.enabled`。使用现有配置覆盖语法，不新建状态库、不复制全局连接参数。其他项目、其他 worktree 不改；同目录窗口共享后台状态，成功提示明确“仅当前项目”。项目只读/路径越界时返回错误。
2. **优先级**：保留 Config 现行合并顺序，保存后清本实例配置缓存再验证 effective enabled；环境/托管等高优先级配置不因运行时 connect 的强制 true 被绕过。目标值不能生效则报错。用户直接编辑配置仍按配置优先级生效。
3. **身份**：名字是现有 MCP 配置键。删除配置后仅有 enabled 的覆盖条目没有 type，不自行启动；同名重新添加连接定义继续遵守该项目保存的意图。项目目录改名视为配置文件随目录移动；symlink 别名由 Instance 归一化，配置路径另作 realpath 边界检查。
4. **写入**：JSONC 单叶补丁，原子替换、文件级锁，不覆盖连接参数、注释及无关设置。写失败不切运行状态。失败不是禁用意图。
5. **竞态**：开关的配置写入串行化，成功写入并验证后才推进实例/名字的操作序号，保存失败不取消已有连接。关闭或新操作令旧结果失效，迟到 client 主动关闭，不能写回 connected/tools。OAuth 完成也经过同一发布前检查。
6. **多窗口**：复用既有 `mcp.tools.changed` 广播，GUI 刷新状态及资源。不新增公共 API/SDK 字段，正式桌面的 v1 后台是本轮实现对象；“已保存”提示仅出现在内建 base sidecar 且协议 v1，远程旧 v1、v2 服务都不冒充已获同等服务端保证。

改前文件清单：新增 `config/mcp-toggle.ts`（原子配置补丁）和独立测试；修改 `config/config.ts`（内部 setter 接入与本实例缓存失效）、`mcp/index.ts`（保存意图/序号/通知）、`app/context/server-sync.tsx`（广播刷新及范围提示）、`opencode/test/fixture/config.ts`（现有 Config 测试替身补齐接口）。前三个产品文件，另一个现有测试文件，总计 4 个上游文件；Config、MCP 及既有测试替身命中 R4。

R1：独立 wrapper 可以实现文件补丁，却无法接入私有 Config 缓存与 MCP client 发布时序，必须在上述内部边界注入；避免把运行时私有状态复制为第二套。Config/MCP 接线将超过 5 行，因此先在本文列明不可只靠前端保存或外层 wrapper 的原因；完整 diff、风险与测试随 3-changelog 的 R4 报告提交审查，未批准前不提交黑名单改动。
