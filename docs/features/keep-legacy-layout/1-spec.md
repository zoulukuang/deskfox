# 需求 — 不跟随上游 v2 换代,DeskFox 默认经典布局

**提出**:user,2026-08-11(`upstream-sync-2026-08` 四段 merge 完成、v2 真机试用之后)
**规模**:Large 口径(触动 ≥5 个上游文件;净 +271/−31 行,按行数是 Medium)
**分支**:`sync/upstream-2026-08-10`(接在上游同步之后,同分支)

> ⚠️ **文档时序说明(与规范的偏差,如实记录)**:规范要求 Large 的 1-spec 由 user **改前**审签。
> 本 feat 的实际过程是 user 在真机上逐项指认问题、当场拍板方向,开发随即跟进,spec/plan/changelog
> 三文档在收口阶段补写。本文档是**事后追认**版本,决策内容全部来自 user 当时的明确指示(逐条标注)。

## 一、一句话

上游 v1.17.19+ 把 v2 界面设成默认,user 试用后决定**不采用**;DeskFox 回到 fork 经典布局做默认,
并堵死上游把用户推向 v2 的 4 条路径,同时补回上游 merge 过程中被冲掉的 8 处 fork 交互。

## 二、背景

`upstream-sync-2026-08` 的 spec 决策 **D1** 是"跟随上游 v2 换代"。四段 merge 完成后的真机验收
发现:v2 是**整套新组件**,fork 定制留在 legacy 组件上 → 「代码还在、用户点不到」共 7 项
(2 项当场修,5 项立 REQ-106)。user 2026-08-11 真机试用 v2 后**推翻 D1**:
界面本身也不合用,不跟随,回经典布局。

**这不是"暂时回退"**:开关保留,用户仍可自愿切到 v2 试用;只是 DeskFox 的默认与强制路径全部指向经典布局。

## 三、需求内容(user 逐条拍板)

### R-1 经典布局成为默认(user 2026-08-11)

上游有 **4 条独立路径**会把用户推到 v2,少堵一条就会在某个时点自己切回去:

| # | 路径 | 上游行为 | 本 feat |
|---|---|---|---|
| ① | 渠道默认 | 非 prod 渠道默认 v2 → dev/local 档默认 v2 | 全渠道默认 legacy |
| ② | 新档案默认 | `newLayoutDesignsDefault = true` | `false` |
| ③ | 旧界面退役日 | `2026-09-14` 到期强制 v2 且忽略用户开关 | 不设退役日(`null`) |
| ④ | 版本升级迁移 | 升到 ≥1.17.19 一次性强切 v2 | 不强切 |

### R-2 标题栏图标锚左恢复(user 点名)

经典布局下工具组(文件树/审查/终端等)挂标题栏**左上**,贴近它们控制的左侧面板(REQ-041 图标锚左解耦的 UI 微调)。

### R-3 全面比对补回上游 merge 冲掉的 fork 交互(user 要求"对新旧版本做严密的功能比对")

上游 merge 会冲掉**调用点**而留下定义,表现为"定制静默失效"—— 需系统性比对,不是被动打补丁。

## 四、验收标准

1. **不种任何设置**时进来就是经典布局(自动断言,不靠人眼);
2. 4 条推 v2 路径逐条有单测钉住;
3. 8 处补回的交互在 **local 档真机**逐项确认(CDP,非 mock);
4. 上游原逻辑**不删只停用**(改名保留 + 测试继续覆盖),保证下次 merge 能正常接上游改动;
5. v2 路径下的行为不被本 feat 破坏(用户自愿切 v2 仍可用);
6. 回归:typecheck 全绿 / app 单测除 REQ-105 Win 基线 3 红外全绿 / e2e 相关 spec 全绿。
