## 实现契约

1. 两站相同 Node 制品、不同 PUBLIC_ORIGIN 与本地持久目录；独立单写进程，loopback 监听。复用 enterprise 分享页面，独立 fork 仓储和 API；原云 adapter 保持可用。
2. 单分享单原子信封包含元数据、快照与状态。随机高熵恢复键建立幂等创建；同键不同会话冲突，取消后不可重建。写临时文件、fsync、rename、目录 fsync；删除先原子墓碑再清正文。公开读取只返回 ready 快照，不返回 secret。
3. ID/路径、请求结构、会话/消息/part 关系、条目数、请求与累计字节均校验。固定服务 origin，不信任 Host。关闭独立服务的 SST 管理入口，管理动作走独立 CLI。动态 API、页面和 RPC no-store，取消后返回真实 404。OG 图片同源，不向第三方带会话标题。
4. 本地 durable operation 在发起远端 create 前落盘；全局按 Session 串行；初次同步完成后才更新 Session URL。固定来源信息含 base_url、api_resource、原组织身份（无 token）；取消失败保留重试能力，Session 删除保留清理凭据。旧来源按严格白名单迁移，未知来源禁止猜测试密钥。
5. UI 两入口捕获语言目标；在发送创建前检查后端 OpenAPI 的 shareTarget 枚举支持。生成 Client/SDK，不手改生成文件。同步/取消只用持久化来源；不发送新当前账户凭据到旧服务。
6. 服务容量默认实验参数 16 MiB/请求、64 MiB/分享，只用于本地验收；生产参数通过样本压测后确定。运营联系、保留期和备份删除政策尚待答复，作为公开部署门，不阻断本地实现与测试。Windows 真机入口待提供。

## 上游修改必要性

独立仓储/API/运维脚本与来源解析尽量新文件。现有 ShareNext 把目标和账户绑定于每次请求，并异步初次同步；仅 wrapper 无法固定其缓存、事件队列与删除行为，必须调整生命周期。正式 DB 迁移与 HttpApi 参数、SessionShare 自动创建路径无法从 UI wrapper 补偿。页面缓存/错误/OG 必须在既有路由出口调整，否则取消后仍可能公开历史内容。提交前按 R4 出逐文件复核，不自行提交黑名单改动。
