# voice-settings-ui — 语音助手的入口与配置界面

> **规模:Medium~Large**(估 300–600 行,新增设置面板 + 配置持久化链路 + 侧栏入口迁移)。
> **状态:方案已出,待 user 审签,尚未动工。**
> 起因:[voice-acp-bridge](../voice-acp-bridge/) 落地后,语音助手的全部配置只能改 env
> (`DESKFOX_VOICE_COORDINATOR_MODEL` / `DESKFOX_VOICE_TASK_MODEL` / `DESKFOX_VOICE_SLEEP_SECONDS` …)。
> DeskFox 面向非编码用户,改 env 不是可接受的配置方式。
> user 2026-08-25 提出三件事:配置进界面、语音入口从顶部栏挪到左侧齿轮上方、绑定项目也做成配置项。

## 0. 一句话

给语音助手一个**能看见状态、能改配置**的正经入口:侧栏图标(开关 + 状态卡片)+ 设置里的「语音助手」tab。

## 1. 背景与动机

voice-acp-bridge 把后端链路理顺了,但用户侧留下三个空白:

| 空白 | 现状 | 后果 |
|---|---|---|
| 配置无界面 | 只能改 env | 非编码用户根本改不了;改完还要自己重启语音 |
| 状态不可见 | 顶部栏一个图标,只有开/关 | **用户不知道说完话任务会落到哪个项目、用什么模型**;落错了也无从判断 |
| 入口位置 | 顶部栏,且只在打开项目时显示 | 与"常驻助手"的定位不符;user 希望挪到左侧齿轮上方 |

## 2. 设计原则:按使用频率分处,而不是全塞进一个入口

user 问过"模型配置和绑定项目是不是都跟启动图标放一起"。**部分是** —— 按频率拆:

| 事项 | 放哪 | 频率 |
|---|---|---|
| 开 / 关语音 | 侧栏图标**点击** | 每天多次 |
| 「活会落到哪个项目 / 用什么模型」 | 侧栏图标 **hover 卡片** | 高频**查看**、低频修改 |
| 模型、绑定项目、唤醒词 | 设置 →「语音助手」tab | 配一次管很久 |

全塞进图标的问题:每次只想开个语音都要面对一堆配置项;而配置挤进悬浮面板还会占掉"一眼看清状态"的空间。

## 3. 侧栏入口

位置:齿轮**上方**(user 指定)。

```
  [项目头像 ×N]
  [ + ]
  ─────────────
  [ 🎤 ]   ← 新增
  [ ⚙ ]
  [ ? ]
```

- **点击** = 开 / 关,沿用现有 `voice_start` / `voice_stop`
- **hover** = 状态卡片(本 feat 最想补的东西):

```
┌─────────────────────────────┐
│ 语音助手 · 已开启            │
│ 派活到:Finance             │
│ 干活模型:Claude Opus       │
│ ───────────────────────────│
│ 打开语音界面    ⚙ 设置      │
└─────────────────────────────┘
```

理由:用户对着麦克风说完话,现在**完全不知道任务会落到哪个项目、用什么模型**。
这三行把它变成一眼可见,实现成本很低,却是可用性的分水岭。

### 3.1 已知约束:图标

`IconButton` 只接受图标字典里的 `name`(`packages/ui/src/components/icon-button.tsx:5-9`),
而 **`packages/ui/` 在黑名单**(改动规则 §4.1),麦克风图标加不进去。两条路:

| 选项 | 代价 |
|---|---|
| A. `Button variant="ghost"` + 内联 SVG(现 `voice-dispatch-button.tsx` 就是这么干的) | 与齿轮/帮助的像素对齐要手调 |
| B. 挑一个现有图标近似(`bubble-5` / `brain` / `prompt`) | 语义不准,用户认不出这是语音 |

**倾向 A** —— 麦克风的语义不可替代;为图标动黑名单(R4 override,季度配额 ≤2 笔)不值。

### 3.2 已知风险:`directory` 来源变化不是纯 UI 改动

顶部栏那个按钮的 `directory` 来自路由 `params.dir`,**只在项目页有值**;侧栏是全局常驻的。
而 `voice_status` 这个 5 秒轮询**顺手承担着「告诉语音桥当前项目是哪个」的职责**
(`ipc.ts` 的 `writeActiveProject`,是 voice-acp-bridge 唯一的项目跟随通道)。

⇒ 改 `directory` 的来源 = 改语音桥的"当前项目"判据。迁移时必须一并想清楚:
home 页(无项目)时语音按钮是禁用、还是沿用上一次的项目。

## 4. 设置 →「语音助手」tab

放在**「桌面」组**(它是本机功能,不是服务器配置),排在飞书之后。
飞书 tab 是现成的 fork 先例(`settings-feishu.tsx` + 两套 dialog 各挂一行),照它做即可。

面板内容,按重要性排:

### ① 启用开关
与侧栏图标联动。

### ② 派活目标项目
见 §5,**本 feat 唯一需要产品拍板的地方**。

### ③ 模型
- **干活模型**:只读展示「跟随 DeskFox 当前选择」+ 当前实际值
- **分派模型**:下拉可选,默认 `alibaba-cn/qwen3.8-max`

⚠️ 分派模型的下拉**必须过滤掉 claude-code 系**(或至少给强警告):
它们经 claude CLI 中转,**拿不到运行时动态注册的 MCP**,而派活工具正是动态注册的
(见 voice-acp-bridge 的 2-plan D15/D18,A/B 实测过)。
允许用户选一个必然静默失效的选项没有意义。

### ④ 唤醒词与休眠
唤醒词开关、静默休眠秒数(现 env `DESKFOX_VOICE_SLEEP_SECONDS`,默认 180)。

### ⑤ 诊断
「打开语音日志」按钮,复用现有 `voice_log_path` IPC。

### 4.1 模型选择器不要直接复用会话里那个

`ModelSelectorPopover` 默认依赖 `useLocal()` 的**目录作用域**,而设置弹窗从侧栏打开时
可能不在 `/:dir/...` 路由下。**照抄飞书的做法**:IPC 拉 provider 列表 → 普通 `<Select>`
(`feishu-edit-account-dialog.tsx` 已在设置弹窗里跑通),零作用域风险。

## 5. 派活目标项目 —— 待 user 拍板

user 提出"绑定项目应该是个配置项",但现状是**自动跟随 DeskFox 当前打开的项目**
(voice-acp-bridge §3.5)。这是两种不同的产品语义:

| | 自动跟随(现状) | 显式绑定(user 提的) |
|---|---|---|
| 好处 | 零配置,切到哪派到哪 | 确定性强,不会误落 |
| 坏处 | **切去别的项目看一眼东西时说句话,任务就落那儿了** | 换项目工作时容易忘改,任务落到旧项目 |

**方案倾向:默认跟随 + 可锁定。**

```
派活目标
  ○ 跟随当前打开的项目        (默认)
  ● 固定到:  [ Finance  ▾ ]   [选择其他目录…]
```

日常单项目工作时"跟随"最省心;长时间跑语音、同时在 DeskFox 里翻别的项目时,"锁定"避免误落。
配合 §3 的 hover 卡片「派活到:xxx」,任何时候都能确认活会落哪。

项目选择器有现成的:`prompt-project-selector.tsx`(纯 props 驱动)或 `useDirectoryPicker()`(选任意目录)。

## 6. 真正的工作量在配置持久化,不在 UI

**语音配置目前完全没有持久化** —— 纯 env,主进程 spawn gateway 时读。要做 GUI 就得补一条链路:

```
设置面板 → IPC → 主进程写 voice-settings.json → spawn gateway 时读
                                             ↘ 桥运行时读(派活目标项目)
```

存储位置建议 `$XDG_STATE_HOME/deskfox/voice-settings.json`,与现有 `voice-active-project.json` 放一起。
**不要**写进 opencode 的共享 config(那会波及用户手敲的会话)。

### 6.1 改了配置怎么生效(必须显式设计)

| 配置项 | 生效方式 |
|---|---|
| 派活目标项目 | 桥每次建 session 时读文件 → **立刻生效** |
| 分派模型 | 在 gateway 的 env 里 → **必须重启网关** |
| 唤醒词 / 休眠 | 同上,env |

⇒ 改模型/唤醒词后,若语音正在运行就**自动重启并给 toast**,不要让用户自己猜为什么没变。
