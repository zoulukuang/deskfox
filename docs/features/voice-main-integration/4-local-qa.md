# 语音 local 真机验收

执行电脑：笑南的电脑；体验人：用户本人。候选代码 `b538afd409`，分支 `feat/voice-main-integration`，未合 main。自动化检查及包哈希见 `3-changelog.md`。

## 打开测试包

测试目录：`/Volumes/ExtSSD/software/Codex/artifacts/voice-local-20261114/`。

1. 双击目录内 **启动语音测试.command**。已打开时继续使用现有窗口；启动器遇到测试端口占用会退出，不结束任何已有进程。
2. 确认窗口顶部有蓝色 **LOCAL**。应停在 **测试项目A**；若未打开，用“打开项目”选择测试目录中的 `测试项目A`。
3. 通过本地版现有“连接提供商”连接 **Alibaba (China)** (`alibaba-cn`)。在应用内输入百炼 API Key，不要发到聊天里。测试环境没有复用正式版凭据。候选默认使用 Qwen3.8 Max，语音识别与播报也需要该凭据的相应权限。
4. 点击顶部麦克风图标“开启语音派活”，在打开的语音页面允许麦克风；按页面提示进入监听。当前准备状态是语音关闭，没有提前录音。

务必通过 `.command` 启动，不单独双击 `.app`；前者负责隔离环境。不要把应用搬入 /Applications，也不要单独移动 `.app`。同目录的 tools/runtime 和固定源码 worktree 都是本次自用测试的组成部分。

## 第一轮：只验最短闭环

说：“你好千问，在当前测试项目创建 `voice-check.txt`，内容写‘语音验收成功’，完成后告诉我。”

验收看四件事：能唤醒并听清；任务出现在 **测试项目A** 的会话列表；文件内容正确；最终播报与实际结果一致。主观听感与麦克风权限需本人确认，自动化无法代签。

回报格式：`唤醒成功/失败；文件成功/失败；播报完整/中断/没有；发生时间与错误原文`。先完成这一步，再继续长任务；凭据、录音内容无需贴给 Agent。

## 第二轮：第一轮通过后

- **长任务 TC-E2**：派一个确实执行不少于 6 分钟的任务，例如等待 370 秒后在测试项目写 `long-check.txt`，保持语音连接，检查最终文件与播报；仅看短测试超时参数不算通过。
- **并发播报 TC-E3**：两条独立任务尽量同时完成，分别写不同测试文件，检查两条结果都完整播报；另测本人开口打断，区分主动打断与播报相互截断。
- **切项目/模型**：切到测试项目B后等至少 5 秒再派活，检查文件归属；立即切换即派活另记实际落点。更换可用模型并实际发一条普通会话后再派活，核对任务模型。
- **生命周期**：有任务时主动关闭语音，验证约定的取消；异常结束语音网关时后端任务继续的场景由 Agent 精确定位测试进程后执行，用户不需要手动结束进程。

所有文件任务限于两个测试 Git 项目。正式版继续正常使用。测试 HOME、配置、数据库独立，但本轮未做限制模型读取整台电脑的文件安全沙箱，也未覆盖飞书等静态业务插件。
