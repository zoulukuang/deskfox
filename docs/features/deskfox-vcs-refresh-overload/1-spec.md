## 问题

2026.12.1 两端都出现文件树一直加载、发消息提示「后台引擎 2 分钟内没有响应」。原因是 Git 差异请求越积越多，占满前端连向本地后台的 6 个连接，其他请求只能排队。后台本身没有崩溃。

两个源头相互放大：

1. **触发放大**：后台监听整个工作区，不读项目 `.gitignore`。Git 忽略目录里的每次变动都会触发一次差异刷新。
2. **单次计算慢**：每个未跟踪文件串行起两个 git 进程。FoxTake 真实副本 186 个文件，一次约 4.7 秒。

## 约束

- 走 R1：优先在 fork 新文件实现，改上游文件每处 ≤ 5 行并加 FORK marker。
- 第 2 项的判定方式在动工时定，先评估两种：
  - 前端用已加载文件树节点的忽略标记；
  - 由后台批量判定忽略（需改上游，按 R1 第 3 级先评审）。
- 判定失败或拿不准时，按「需要刷新」处理，宁多刷不漏刷。差异结果不能因此变旧。

## 验收标准

1. 连续大量文件变动期间，文件树展开和回答提交在 1 秒内完成。
2. Git 忽略目录的连续变动不产生差异请求。
3. 已跟踪文件、未忽略的未跟踪文件变动后，审阅面板照常更新。
4. 两端 local 包各自完成修复前后对照，正式版数据不用于故障注入。
