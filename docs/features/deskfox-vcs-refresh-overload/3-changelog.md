# Git 差异刷新占满本地连接

2026-11-11，Windows 电脑。2026.12.1 的现场网络日志记录了同一项目 1,300 多次差异请求，目录树和回答提交等待连接超过 8 分钟。连续文件事件反复使差异查询失效，查询层取消旧结果后，已发出的 HTTP 请求仍在等待。

保留 100 毫秒防抖。差异请求进行中时合并后续刷新，响应结束后再发一次。会话切换工作区或分支时丢弃旧查询键的待刷新。复现用例用同一组文件事件比较修复前后的并发数，并检查目录展开和回答提交。

Windows 电脑在生产前端构建上对照验证。第一条差异响应挂起时，旧构建发出 9 条请求，修复后只发出 1 条，响应释放后补刷 1 条。等待期间目录可展开，回答提交返回成功。生产构建的 4 条相关 Playwright 用例、app 1,197 条单测和 41 条浏览器测试、app 与 e2e 类型检查均通过。正式 Windows 安装版待随发布流程验证。

2026-11-11，Windows 电脑从 `8d979a0a9b` 构建并启动了独立 local 包。用该包的 Windows 后台和生产前端在临时 Git 仓重放 12 次对 Git 忽略目录的快照替换。差异请求挂起时只发出 1 条，期间文件树展开约 100 毫秒，释放后补刷 1 条。带调试端口的启动被自动审批拦截，生产前端在独立 Chromium 中完成负载测试。正式版复发日志仍来自原 2026.12.1 进程，记录了同项目 2,127 条差异请求。

### 两端对比与结论边界

Windows 已由现场网络日志和对照验证确认 Git 差异刷新请求积压。macOS 同样具备「高频文件变化、重开恢复、后台未异常退出」特征，因此高度怀疑同一机制，但缺少 macOS 请求排队现场，尚不能写成两端根因完全一致。后台仍可运行不代表前端连接未堵塞，健康检查也不能替代用户请求可用性检查。

另发现一条独立的文件树刷新路径：`packages/app/src/context/file.tsx` 的 `refreshDir` 使用 `force: true`，`file/tree-store.ts` 的强制刷新绕过 inflight 去重。Windows 已修的是 `pages/session.tsx` 的 Git 差异刷新，不是此目录列表路径；不要将两者混称为同一处修复，也不要在缺现场证据时扩展修复范围。此前找到的 2026-07-28 Windows 渲染进程 OOM 属另一事件，不作为本次同因依据。

### 网络证据已补齐

从正在写入的 Chromium NetLog 临时目录复制 `constants.json` 与 10 个环形事件文件，未停止录制。保存片段覆盖北京时间 11:55:00.305 至 12:01:35.533，共 140,867 条完整事件；部分请求的创建时间早于此窗口，通过发送事件携带的 `source.start_time` 回查。环形日志并非故障全过程，请求数量仅是本片段下界，不与 Windows 的完整现场计数直接比较。

按 URL_REQUEST source ID 去重，并结合 URL 事件与实际 HTTP 请求行恢复路径，片段内至少识别出 FoxTake 同项目 51 条 `/vcs/diff` GET。记录到 391 条 `SOCKET_POOL_STALLED_MAX_SOCKETS_PER_GROUP`，不是 391 个独立请求；该事件直接表明存在同组连接数上限造成的等待。四条事务另以实际请求行、响应状态及时间戳独立核对：

发送前等待包括连接获取及可能的 CORS 预检，不能全部视为后台处理时间。根目录只需 13 毫秒响应，却在发送前等待约 84 秒，结合明确的 socket pool stalled 事件，已将「文件树加载不出来」定位为客户端连接排队，而非目录扫描本身卡死。多条同项目 Git 差异请求在同一秒附近创建，等待超过 4 分钟后仍逐条实际发出并返回 200，与 Windows「查询结果被取消，但 HTTP 请求没有随之消失」的缺陷相符。

后台继续执行其他会话，无退出或看门狗重启日志；独立无鉴权请求在约 8 毫秒内得到 401，证明监听与 HTTP 入口有响应，但不冒充认证健康检查通过。`sqlite3 -readonly` 确认当前授权文案会话 11:56:31 的带引用续发已落盘且助手继续运行。截图中的超时提示可能属于另一条会话/尝试，不能把此次成功续发当作截图对应原消息一定送达或一定未送达的证明。

### 结论与后续边界

本次不再只是根据文件事件密度怀疑：macOS 已直接命中与 Windows 相同的「Git 差异请求积压并争用前端本地连接，其他请求排队」机制。两分钟提示来自 `submit.ts` 的 120,000 毫秒送达截止；客户端排队可以超过该阈值，所以后台未崩也会触发提示。不能通过单纯延长截止时间或重启来修掉请求积压。

修复方向继续复用本分支 `8d979a0a9b` 的差异刷新合并；目录列表强刷仍是独立风险，当前不另扩修复。尚未在 Mac local 包进行修复前后负载对照，不能声称分支已通过 Mac 验收或可发布。现场定位完成后暂留分支，退出暂停条件更新为用户明确安排 Mac local 验证/修复推进或再次补充故障现场；不合 main、不发布。
