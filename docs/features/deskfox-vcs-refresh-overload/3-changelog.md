# Git 差异刷新占满本地连接

2026-11-11，Windows 电脑。2026.12.1 的现场网络日志记录了同一项目 1,300 多次差异请求，目录树和回答提交等待连接超过 8 分钟。连续文件事件反复使差异查询失效，查询层取消旧结果后，已发出的 HTTP 请求仍在等待。

保留 100 毫秒防抖。差异请求进行中时合并后续刷新，响应结束后再发一次。会话切换工作区或分支时丢弃旧查询键的待刷新。复现用例用同一组文件事件比较修复前后的并发数，并检查目录展开和回答提交。

Windows 电脑在生产前端构建上对照验证。第一条差异响应挂起时，旧构建发出 9 条请求，修复后只发出 1 条，响应释放后补刷 1 条。等待期间目录可展开，回答提交返回成功。生产构建的 4 条相关 Playwright 用例、app 1,197 条单测和 41 条浏览器测试、app 与 e2e 类型检查均通过。正式 Windows 安装版待随发布流程验证。

2026-11-11，Windows 电脑从 `8d979a0a9b` 构建并启动了独立 local 包。用该包的 Windows 后台和生产前端在临时 Git 仓重放 12 次对 Git 忽略目录的快照替换。差异请求挂起时只发出 1 条，期间文件树展开约 100 毫秒，释放后补刷 1 条。带调试端口的启动被自动审批拦截，生产前端在独立 Chromium 中完成负载测试。正式版复发日志仍来自原 2026.12.1 进程，记录了同项目 2,127 条差异请求。

### 两端对比与结论边界

Windows 已由现场网络日志和对照验证确认 Git 差异刷新请求积压。macOS 同样具备「高频文件变化、重开恢复、后台未异常退出」特征，因此高度怀疑同一机制，但缺少 macOS 请求排队现场，尚不能写成两端根因完全一致。后台仍可运行不代表前端连接未堵塞，健康检查也不能替代用户请求可用性检查。

另发现一条独立的文件树刷新路径：`packages/app/src/context/file.tsx` 的 `refreshDir` 使用 `force: true`，`file/tree-store.ts` 的强制刷新绕过 inflight 去重。Windows 已修的是 `pages/session.tsx` 的 Git 差异刷新，不是此目录列表路径；不要将两者混称为同一处修复，也不要在缺现场证据时扩展修复范围。此前找到的 2026-07-28 Windows 渲染进程 OOM 属另一事件，不作为本次同因依据。

## 暂停决定与复发检查点（2026-11-12）

用户决定：本问题的排查和已有代码统一留在同一子分支，先提交，等再次出现问题后继续。退出暂停条件为用户报告复发或明确要求恢复排查；不合并 main、不发布、不追加修复，也不将 Windows 已有验证写成 macOS 验收通过。

复发时优先保留仍在运行的现场，不先重启或清理缓存：

1. 记录时间、版本、项目、正在执行的任务及具体失效操作，区分单个长工具等待与整个文件树/提交不可用。
2. 同时检查前端 Network 的 `/vcs/diff` 数量、未完成请求及连接排队时间，并从独立客户端检查后台健康，判断「后台假死」还是「前端连接被占满」。
3. 对齐文件事件密度、Git 差异刷新与目录列表请求；若 Git 差异正常，再追独立的目录刷新路径，不凭日志行数推算请求数。
4. 导出并在本机私有位置保留日志、必要的网络采样和进程信息后再决定是否重启；日志启动清理窗口为 7 天，原件可能过期。网络日志可能包含私有路径或凭据，不直接提交仓库。
5. 若证据命中，再用本分支的独立 local 版做 macOS 对照验证；正式运行中的 DeskFox 和数据不用于故障注入。

本次仅补文档和索引，检查 `git diff --check`，不重跑产品测试；Windows 既有验证范围以上文为准。
