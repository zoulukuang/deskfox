## 配置和运维

本目录保存已安装的 systemd、env 示例和 Nginx snippets。env 实例仅 PUBLIC_ORIGIN 按区域不同；没有密码。实际 env 权限为 root:deskfox-share 0640。
服务用户 `deskfox-share` 无登录 shell；整个 Node 进程持有 `writer.lock`；第二写者会失败。服务内存上限 768MiB，最大任务数 64；自动重启。数据不在官网 rsync --delete 目录下。

初始保护参数：单请求 16MiB、单分享 64MiB、磁盘至少余 1GiB、每 IP 每分钟 120 请求/10 创建、进程并发 16；Nginx 动态路由 5r/s、burst 20、每 IP 10 连接。已验证边界生效；这些是初始上限，不代表完成业务负载压测。根据上线流量再调整，不能通过删除墓碑释放容量。

`share-http.conf` 安装为 `/etc/nginx/conf.d/deskfox-share.conf`；其余三个 conf 安装到 `/etc/nginx/snippets/deskfox-share/`。站点 TLS server 精确 include `share-locations.conf`；只代理分享 API、公开页、SSR/RPC 和构建资源，官网仍使用原静态根目录。新服务器必须先安装这些文件和服务，再更新站点 Nginx。`deploy-cn.sh --nginx` 不负责首次安装分享服务；普通两站页面发布不动分享数据。

海外 443 原有 SNI 分流保持：普通 HTTPS 到 8444，Reality 流量到原 8443。为使分享限流获得真实 IP，前置 stream 发送 PROXY 协议，8444 接收；Reality 经新增 loopback 8445 中继去掉 PROXY 头后转给 8443。对照见 `deskfox.ai/nginx/share-stream.conf.example`，它是现有 nginx.conf 的 stream 块，不可额外重复 include。分享 TLS server 仅信任 127.0.0.1 的 PROXY 源；公网伪造 X-Real-IP/X-Forwarded-For 实测不能覆盖。

海外首次 reload 时发现 sites-enabled/deskfox.ai 是独立文件，且两个旧 .bak 文件被 Nginx 重复加载；健康检查失败后自动回退。最终将备份移出 enabled，正式入口改为指向 sites-available 的软链，重新 nginx -t/reload/公网验收通过。今后不能把 .bak 文件放进 sites-enabled。
